# Logistic Balar - מערכת דרישות לוגיסטיות לקורסים

מערכת קלה להגשת "פורמט דרישה לוגיסטית" לקראת קורסים, וייצוא דוח מרוכז וקריא לצוות הלוגיסטיקה.

## מה המערכת עושה

1. **טופס הגשה** (`/`) - כל מדריך/מפקד קורס ממלא טופס קצר ונוח (מובייל-פרנדלי, RTL בעברית):
   שם הקורס, תאריך ושעות, כמות חניכים, צורך בכיתה ושעותיה, רשימת אמל"ח נדרש (פריט + כמות),
   רשימת ציוד לוגיסטי נדרש (פריט + כמות) והערות. אפשר להוסיף כמה שורות פריטים שרוצים.
2. **עמוד ניהול** (`/admin.html`) - מוגן בסיסמה, מציג את כל הדרישות שהוגשו, מאפשר סינון לפי
   תאריך קורס, מחיקת דרישה שגויה, ולחיצה על **"ייצוא דוח מסודר"** מייצרת דף HTML מעוצב וקריא
   שמחלק את כל הדרישות לפי קורס/מגיש, כולל סימון ברור לדרישות שהוגשו **באיחור** (אחרי השעה
   12:00 של היום שלפני הקורס). ניתן להדפיס/לשמור כ-PDF ישירות מהדוח בלחיצת כפתור.
3. **ייצוא אוטומטי מתוזמן (אופציונלי)** - אם מגדירים משתנה סביבה `EXPORT_CRON`, השרת ייצור
   אוטומטית קובץ דוח HTML בתיקייה `data/exports/` בשעה שתוגדר (למשל כל יום ב-15:00), כדי
   שיהיה קובץ מוכן וממתין ברגע שחלף מועד ההגשה.

## התקנה והרצה

```bash
npm install
cp .env.example .env   # ניתן לערוך ולשנות את ADMIN_PASSWORD
npm start
```

השרת יעלה בכתובת `http://localhost:3000` (או הפורט שהוגדר ב-`PORT`).

- טופס הגשה לכלל המשתמשים: `http://localhost:3000/`
- עמוד ניהול (סיסמה): `http://localhost:3000/admin.html`

## משתני סביבה (`.env`)

| משתנה | ברירת מחדל | תיאור |
|---|---|---|
| `PORT` | `3000` | הפורט שעליו רץ השרת |
| `ADMIN_PASSWORD` | `balar2026` | הסיסמה לעמוד הניהול |
| `EXPORT_CRON` | - | ביטוי cron לייצוא אוטומטי מתוזמן, לדוגמה `0 15 * * *` (כל יום ב-15:00) |

## מבנה הנתונים

הדרישות נשמרות בקובץ `data/submissions.json` (לא נשמר בגיט - נוצר אוטומטית בהרצה
ראשונה). לפריסה אמיתית מומלץ לוודא שהתיקייה `data/` נשמרת בין הפעלות (דיסק קבוע / Volume),
או לחבר מסד נתונים חיצוני בהמשך אם נדרש.

## פריסה כאתר חי ב-Render (מחובר ל-GitHub)

בריפו כבר קיים קובץ `render.yaml` שמגדיר את השירות אוטומטית. כדי לפרסם:

1. להיכנס ל-[dashboard.render.com](https://dashboard.render.com) (אפשר עם חשבון GitHub).
2. **New +** → **Blueprint** → לבחור את הריפו `Logistic_Balar` (ולוודא שהברנץ' הנכון נבחר).
3. Render יזהה את `render.yaml` וייצור אוטומטית שירות Node עם סיסמת המנהל `balar2026`
   (אפשר לשנות בעמוד ה-Environment של השירות ב-Render בכל שלב).
4. לאחר כמה דקות יינתן קישור ציבורי בסגנון `https://logistic-balar.onrender.com` -
   זה קישור הטופס. עמוד הניהול נמצא ב-`/admin.html`.
5. כל פוש לענף המחובר ב-Render יגרום לדיפלוי אוטומטי מחדש.

**⚠️ הערה חשובה לגבי שמירת נתונים בתוכנית החינמית:** בתוכנית ה-Free של Render מערכת
הקבצים היא **זמנית (ephemeral)** - כאשר השירות "נרדם" מחוסר פעילות (כ-15 דקות) או
מתעדכן מדיפלוי חדש, כל הקבצים בתיקיית `data/` (כלומר כל הדרישות שהוגשו) **יימחקו**.
זה מתאים לבדיקה/הדגמה, אבל **לא מומלץ לשימוש אמיתי** בלי אחת מהאפשרויות הבאות:

- שדרוג לתוכנית בתשלום (Starter ומעלה, ~7$/חודש) + הוספת **Persistent Disk** מחובר
  לתיקיית `data/` בהגדרות השירות ב-Render (כך הנתונים נשמרים גם אחרי אתחול/דיפלוי).
- מעבר בעתיד לאחסון חיצוני (מסד נתונים כמו Render PostgreSQL / Supabase) במקום קובץ
  JSON מקומי - שינוי שאפשר לבצע בהמשך אם תרצו.

אם מדובר בשימוש חד-פעמי או קצר טווח (למשל להריץ ולסגור תוך יום-יומיים), התוכנית
החינמית מספיקה כמו שהיא.

## פריסה בסביבות אחרות

המערכת היא שרת Node.js/Express רגיל וניתן להריץ אותה גם בכל שירות Node אחר (Railway,
Fly.io, VM רגיל וכו') - באותו אופן: להריץ `npm install && npm start` ולוודא שהתיקייה
`data/` נשמרת בין הפעלות (דיסק קבוע / Volume) אם רוצים שהנתונים לא יימחקו.
